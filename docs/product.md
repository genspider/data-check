数据比对 Studio 产品说明

1. 产品定位

一个浏览器端数据比对 Studio：用户上传 A/B 两份表，系统按表结构指纹精确匹配已发布的比对规则，一键应用即出结果。规则强绑定表结构，由用户定义并发布，他人可复用。数据全程不出浏览器，服务器只维护规则与元信息。

一句话：上传表 → 匹配规则 → 一键执行 → 看结果 → 留档导出；规则可定义、可发布、可复用，数据不出端。

2. 核心概念

概念 定义
规则 描述“怎么比”的完整定义：主键列、比对列、忽略列、A/B 列映射、归一化、容差、空值策略、差异严重级别。强绑定具体表结构（列名+类型），不做模糊泛化。
表结构指纹 列名+类型+顺序的哈希，用于规则精确匹配。
文件指纹 行数、列名哈希等元信息，不含内容，用于执行记录追溯。
规则库 服务端维护的已发布规则集合，支持按结构指纹匹配推荐。
执行记录 每次比对的元信息留档：规则 ID+版本+快照、两份表指纹、时间、执行人、摘要指标。
工作台（Studio） 单界面完成上传、规则选择、执行、结果查看的完整流程。

3. 主流程

1. 上传表：用户拖入 A/B 两份文件（CSV/Parquet/JSON/Excel），前端解析，立即计算表结构指纹。
2. 匹配规则：用结构指纹去规则库精确匹配。匹配到 → 推荐规则卡片（名称、发布者、适用场景、版本）；匹配不到 → 显示近似规则（标注差异列/类型不一致），或引导 AI 生成新规则。
3. 一键应用：规则内所有参数预设，点击即执行。前置校验（如主键唯一性）不通过时明确提示“继续/放弃”，不静默出脏结果。
4. 执行比对：DuckDB-WASM 在浏览器内完成全部计算，数据不出端。
5. 查看结果：摘要卡片（总行数、匹配数、差异数、各类型占比、每列差异计数）+ 差异明细（仅 A、仅 B、值不同，列出两边值和差异列）。
6. 留档与导出：执行记录上服务器（仅元信息）；差异明细导出 CSV/Excel 由前端生成，不经过服务器。
7. 反哺规则：基于结果微调规则，存为新版本。

4. 规则定义（Schema 概念级）

```
rule = {
  id, name, version, description, publisher,
  structure_fingerprint: { col_name, type, order }[],   // 强绑定
  key: { columns: [...], uniqueness: block | warn | dedup },
  scope: { filter_a?, filter_b?, common_filter? },       // 可选过滤
  columns: [{
    a_col, b_col,
    role: key | compare | ignore,
    severity: fatal | warn | info,
    normalize: { type_level_default, override },
    tolerance: { kind: abs | rel | round, value },
    null_policy: equal | not_equal | ignore
  }],
  summary_metrics: [...]
}
```

关键语义必须写死：

· 容差：绝对 / 相对 / 四舍五入，公式明确（如 |a-b| <= v 或 round(a,2)==round(b,2)）。
· 字符串归一化：trim 两端 vs 去除全部空白，大小写敏感与否。
· 日期归一化：格式列表，统一解析后比较。
· 空值等价类：NULL / 空字符串 / "NULL" 是否等价。
· 主键唯一性：block（阻断）/ warn（警告继续）/ dedup（按规则去重后比对）。

5. 规则生命周期

· 定义：AI 自然语言生成候选规则（3–5 条语义不同）→ 试跑对比 → 择优确认；也支持手写/导入 JSON/YAML。
· 发布：填名称、描述、适用场景、结构指纹、版本号；系统校验合法性（主键存在、类型兼容、列不重叠）。
· 复用：他人上传表后按结构指纹精确匹配推荐，一键套用。
· 治理：发布权限、版本递增、软删除下架；历史结果保留规则快照，规则变更不影响历史结果。

6. AI 的角色与边界

· 做什么：读两表的结构信息+统计量（可选脱敏样本），生成多条候选规则并附自然语言解释（为什么建议该主键、该容差等）；对匹配失败的表给出近似规则差异说明。
· 不做什么：不执行比对、不碰全量数据、不直接落规则——生成的是“建议”，用户确认后才成为规则。
· 输入限制：只送列名、类型、非空率、唯一值数等元信息；样本行前端掩码/截断，可选关闭。
· 输出校验：生成后跑 schema 校验，不合法则回退或重生成。

7. 数据边界（必须写进产品说明的承诺）

只保存在浏览器（绝不上传）：

· 表数据本体（A/B 文件内容），存 DuckDB-WASM 内存 / IndexedDB / OPFS。
· 比对执行过程与差异明细结果。
· AI 生成规则时的原始样本行（前端脱敏后可选送统计量）。
· 导出文件由前端生成。

保存在服务器（绝不含数据）：

· 规则本体（仅列元信息）、结构指纹、版本与快照。
· 执行记录元信息：规则 ID+版本、两份表的结构指纹+文件指纹（行数、列名哈希）、时间、执行人、聚合摘要指标。
· 用户、权限、规则库目录。

灰色地带定死：

· 聚合摘要（计数类）可上服务器；差异明细具体值绝不上传。
· 结果分享只分享“记录引用+摘要”，不传数据文件。
· 浏览器本地存储提供“一键清除本地数据”，并明确告知数据只在本机。

承诺句：服务器上永远没有表内容、行级差异、样本原始值；只有规则、结构指纹、文件指纹、聚合摘要、执行元信息。

8. 量化口径

· 主口径：替代开发量——覆盖 N 类比对场景，原先需 N 套自研、约 N×X 人天，平台一次开发 Y 人天，节省 Z 人天。
· 辅口径一：典型场景单次耗时——抽样 3–5 个场景，报“从 A 降到 B”。
· 辅口径二：规则复用——规则被复用 M 次 × 每次节省 t 分钟，累计节省。
· 用户边界模糊不回避：价值是“替代重复建设 + 比对能力规则资产化”，不是“服务了多少人”。

9. MVP 边界

先做：单规则精确匹配、主键唯一性校验、类型级归一化+列级容差、三类差异+摘要、规则保存/发布/按指纹匹配、执行记录元信息留档、CSV 导出、AI 生成候选规则+解释。

暂缓：多规则组合（规则集）、过滤条件高级 UI、规则共享权限体系、跨表类型自动转换、结果分享链接。

10. 技术要点

· 比对引擎：DuckDB-WASM，浏览器内执行 SQL，数据本地加载。
· 前端：文件解析 → 结构指纹计算 → 规则匹配 → SQL 生成 → 结果渲染 → 前端导出。
· 服务端：静态资源 + 规则库 API（CRUD、匹配、版本）+ 执行记录 API（仅元信息）+ 用户权限。
· 性能边界：几十万行内流畅；上百万行提示内存上限或分片；大文件走本地服务模式而非纯静态 HTML 模式。
